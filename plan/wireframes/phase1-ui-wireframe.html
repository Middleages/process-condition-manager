0. UI 구성 검토 — Light 버전

제공해주신 레퍼런스 UI의 문서형/light 스타일을 기준으로, 현재 Phase 1 계획의 화면 구성을 재정리했습니다.

검토 결론: 이전 dark mockup보다 이 light 문서형 UI가 Phase 1 논의에 더 적합합니다. 표, 상태 배지, API 매핑, 동작 명세를 한 문서 안에서 같이 볼 수 있어 “화면 설계서”로 사용하기 좋습니다.

레퍼런스 UI에서 채택할 점

항목채택 방향
문서형 좌측 Nav화면, 컴포넌트, 흐름, API 매핑을 한 HTML에서 점프해서 검토한다.
Light 테마실제 업무 화면과 설계 리뷰에 적합한 흰 배경/파란 primary 색상으로 통일한다.
프로젝트 목록 우선Process Catalog와 별개로 사용자가 매일 들어오는 시작점은 Project List로 둔다.
조건표 편집기 구조상단바 + 좌측 layer nav + category tabs + grid + validation panel 구성을 유지한다.
상태/툴팁/흐름 명세셀 상태와 API 호출 흐름을 UI 문서 안에 같이 둔다.

우리 도메인에 맞게 조정한 점

조정이유
Process Catalog 추가Process는 제품/route 전체 흐름이므로, 프로젝트 생성 전 적재 process를 검색/preview하는 화면이 필요하다.
Backbone 제품 선택 단순화 보류Phase 1에서는 process 선택 → project 생성 → sheet_layer 파생 흐름을 먼저 검증한다.
Layer 100개 미만 기준좌측 layer nav와 grid sticky row/column 구조로 충분히 검토 가능한 규모다.
Parameter 약 200개 기준category tab과 horizontal grid scroll을 기본 UX로 둔다.
