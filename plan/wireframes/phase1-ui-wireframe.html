Primary flow

도메인 정의 (D-14)

Process = 적재로 들어오는 구조(뼈대). partid, processid, stepseq, area 같은 컬럼으로 된 layer/step 목록. 조건 값 없음, 읽기 전용.

Project = process 하나를 골라 만든 조건표 (구조 + 셀 값 + 상태/버전).

백본 = 값의 원천이 되는 기존 프로젝트. 백본을 매칭하는 순간 "프로세스가 프로젝트로 변신"한다.

적용 정책

P1-D1 백본과 미매칭인 layer는 빈 값으로 시작
P2-D3 빈 셀은 "해당 없음"이 아닌 편집 가능한 빈 값
숫자 키 1–5로 화면 전환

동작 메모 — Process Catalog

  1. process는 구조만 보여준다 — partid/processid/stepseq/area 기반 layer 리스트. 값·매핑 정보는 여기 없다 (값의 원천은 백본 프로젝트, D-14).
  2. "조건표" 컬럼으로 process ↔ 프로젝트 대응 상태를 표시 — "없음"인 process가 생성 대상. "조건표 없는 process만" 필터가 신규 작업 발굴 동선.
  3. 이미 조건표가 있는 process에서 "생성"을 누르면 안내: 장기 목표는 process당 활성 프로젝트 1개 (중복 생성 정책은 P1-D6).
  4. 검색/필터 속성(partid, area 등)은 적재 스키마 확정 후 최종 확정 (P1-D2).
  5. API: GET /processes?query=&cursor=, GET /processes/{key}/layers.

동작 메모 — Project Create

  1. 구조와 값의 분리가 이 화면의 핵심: ① process = 구조(적재), ② 백본 프로젝트 = 값(기존 조건표). 매칭은 두 선택의 조합에서 계산된다 — process 자체에는 매핑/값이 없다 (D-14).
  2. 백본 후보는 기존 프로젝트 목록 (Approved 우선 정렬). 후보마다 layer 매칭률을 미리 보여줘 선택을 돕는다.
  3. layer 매칭 키는 미확정(layer 이름? stepseq? area 조합?) — P1-D5. 와이어프레임은 이름 기준 예시.
  4. "백본 없이 시작" 옵션이 부트스트랩 경로 — 최초 프로젝트(참조할 백본이 없을 때)는 빈 조건표 + 엑셀 붙여넣기로 시작.
  5. ③은 dry-run API 결과. 생성은 단일 트랜잭션: sheet_layer 파생 + cell_value 복사 + change_event(backbone_copy).

동작 메모 — Project Detail · 백본 교체

  1. 레이어별 백본 교체의 소스는 다른 프로젝트(의 layer)다 — 생성 시 백본 선택과 같은 원리의 layer 단위 버전.
  2. "백본 소스" 컬럼으로 layer별 조합 상태(Main/교체됨/미매칭)를 상시 노출 — 어떤 layer가 어느 조건표에서 왔는지 추적 가능.
  3. "값 채움" 바로 미매칭·빈 layer를 시각적으로 발견 → 교체 또는 엑셀 붙여넣기로 채우는 동선.
  4. 교체 modal 3단계: 소스 프로젝트 검색 → layer 선택(이름 일치 우선 추천) → diff 미리보기 후 적용. 미리보기 없이 덮어쓰지 않는다.
  5. API: POST /projects/{id}/layers/{layer_key}/backbone-replace — body: 소스 project_id + layer_key. 교체 이력은 Phase 4 타임라인에서.

동작 메모 — Sheet Editor PoC

  1. 카테고리 탭·컬럼 그룹은 파라미터 레지스트리에서 동적 생성 (layer의 area와는 다른 축).

  3. Paste staging: 붙여넣기는 즉시 반영이 아니라 staging(점선) → 타입 검사 → 적용/취소. 적용 시 dirty로 전환.
  4. 비보유자 화면(Phase 2): 상단에 "OO 님이 편집 중 — 읽기 전용" 배너 + 편집/저장/붙여넣기 비활성.
  5. 이 화면은 그리드 PoC(phase-1-tasks T7) 검증 대상 — 실제 그리드는 Glide Data Grid vs RevoGrid PoC로 확정.
