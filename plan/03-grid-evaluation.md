# 03. 그리드 라이브러리 평가

## 1. 배경

기존 시스템은 AG Grid를 사용했으나 두 가지 문제가 있었다.

1. **엑셀 붙여넣기가 잘 되지 않았다.** 원인은 구현 실수가 아니라 라이선스다 — AG Grid에서 범위 선택(Cell/Range Selection)과 클립보드 복사/붙여넣기는 **Enterprise(유료) 전용 기능**이다. Community 버전으로는 대량 붙여넣기 UX를 만들 수 없거나 전면 커스텀이 필요하다.
2. **100~200개 컬럼의 가독성** — 컬럼명과 값이 사용자에게 잘 보이도록 하는 장치가 부족했다.

제약 조건: **유료 라이선스 불가, 사내망(폐쇄망) 배포** (D-12).

## 2. 평가 기준

| # | 기준 | 가중치 | 설명 |
|---|------|--------|------|
| C1 | 엑셀 범위 붙여넣기 | ★★★ | 엑셀에서 복사한 다중 셀(TSV)을 범위 선택 후 붙여넣기. 사용자의 주 작업 방식 |
| C2 | 라이선스 | ★★★ | 상용 서비스에 무료 사용 가능 (MIT/Apache) |
| C3 | 대량 컬럼 성능 | ★★★ | 200 컬럼 × 60 행에서 컬럼 가상화 포함 쾌적한 스크롤/편집 |
| C4 | 셀 타입별 에디터 | ★★ | 숫자/문자/선택지(드롭다운) 에디터, 레지스트리 기반 동적 구성 |
| C5 | 셀 상태 표시 | ★★ | 검증 오류·더티·코멘트 셀 하이라이트, 커스텀 렌더링 |
| C6 | 컬럼 그룹/고정 | ★★ | 카테고리별 그룹 헤더, 핵심 컬럼 pinning |
| C7 | 성숙도/유지보수 | ★★ | 커뮤니티 규모, 릴리스 활성도, 문서 품질 |
| C8 | 폐쇄망 적합성 | ★ | npm 패키지 자체 번들로 완결 (CDN/외부 호출 없음) |

## 3. 후보 비교

| 후보 | 라이선스 | C1 붙여넣기 | 비고 |
|------|----------|-------------|------|
| **AG Grid Community** | MIT | ✗ (범위선택·클립보드 없음) | 성숙도·컬럼 그룹·가상화는 최상. 붙여넣기를 쓰려면 범위 선택부터 자체 구현해야 함 — 기존 실패 지점 재현 위험 |
| **Glide Data Grid** | MIT | ◯ (범위 선택 + copy/paste 내장) | Canvas 렌더링으로 대량 데이터 성능 최상급. 에디터/스타일은 DIY 성격이 강함. React 전용 |
| **RevoGrid** | MIT | ◯ (범위 선택 + 클립보드 내장) | 엑셀 유사 UX 지향. 컬럼 그룹/고정 지원. 커뮤니티 규모는 상대적으로 작음 |
| **Univer** | Apache-2.0 | ◎ (스프레드시트 그 자체) | 완전한 엑셀 대체품. 다만 "구조화된 데이터 바인딩 + 검증"보다 자유 문서 편집에 가까워 조건표처럼 스키마가 고정된 그리드에는 제어 비용이 큼 |
| Handsontable | 상용 (비상업만 무료) | ◎ | **라이선스 제약으로 탈락** |
| Jspreadsheet CE | MIT (CE) | △ | CE 기능 제한 폭이 커서 후순위 |

> 표의 지원 여부는 계획 수립 시점의 파악이며, PoC 첫 단계에서 각 후보의 최신 버전 기준으로 재검증한다.

## 4. 권고

**1차 후보: Glide Data Grid vs RevoGrid** — 둘 다 C1(붙여넣기)과 C2(라이선스)를 기본 충족한다. AG Grid Community는 C1 자체 구현 부담 때문에 "탈락 후보와의 비교 기준선"으로만 PoC에 포함한다.

- **Glide Data Grid**가 유리한 경우: 성능·부드러운 UX 최우선, 커스텀 렌더링(셀 상태 표시)을 canvas로 직접 그리는 비용을 감수할 때.
- **RevoGrid**가 유리한 경우: 엑셀 유사 UX를 빠르게 확보하고 싶고, 컬럼 그룹 등 기본 제공 기능을 그대로 쓰고 싶을 때.

어느 쪽이든 [01-architecture.md](./01-architecture.md)의 **그리드 어댑터(P4)** 뒤에 두므로, PoC 결정이 이후 전체를 인질로 잡지 않는다.

## 5. PoC 계획 (Phase 1과 병행)

동일한 시나리오를 두 후보(+기준선 AG Grid Community)로 구현해 비교한다.

**PoC 시나리오:**
1. 레지스트리 mock(파라미터 200개, 카테고리 5개)에서 컬럼 동적 생성
2. 60행 × 200컬럼 데이터 로드, 스크롤/편집 체감 성능 확인
3. 엑셀에서 10행 × 20열 복사 → 범위 선택 → 붙여넣기 → 타입 불일치 셀 표시
4. 선택지(choice) 컬럼 드롭다운 에디터
5. 검증 오류 셀 빨간 표시 + 특정 셀로 스크롤 점프
6. 카테고리 탭 전환(컬럼 부분집합 표시) + 핵심 컬럼 고정

**판정:** 시나리오 3(붙여넣기)과 2(성능)에서 우열이 갈리면 그것으로 결정. 동률이면 C7(성숙도) 우선.

## 6. 컬럼 가독성 전략 (라이브러리 무관 공통 설계)

100~200 컬럼 문제는 그리드 선택만으로 해결되지 않는다. 다음을 UI 설계에 포함한다:

- **카테고리 탭/필터**: 레지스트리의 카테고리 속성으로 컬럼 부분집합만 표시. 카테고리가 관리자 설정이므로 탭도 동적 생성
- **핵심 컬럼 고정(pinning)**: layer명 등 식별 컬럼은 항상 좌측 고정
- **헤더 툴팁**: 레지스트리의 `description`을 헤더 hover로 노출. 축약된 컬럼명의 전체 의미 전달
- **컬럼 검색-점프**: 컬럼명 검색으로 해당 컬럼으로 즉시 스크롤
- **개인 컬럼 프리셋** (후순위): 자주 보는 컬럼 조합 저장

## 7. 결정 (Phase 1 T7)

### 7.1 산출물

- **그리드 어댑터 인터페이스 초안**: `frontend/src/grid/types.ts` — 동적 컬럼, 셀 타입별 에디터, 카테고리 탭, 컬럼 고정/툴팁/검색-점프, 조건 행 그룹핑 + POR 컬럼, 붙여넣기 스테이징, 셀 상태 오버레이, 더티 셀 배치를 계약으로 고정했다. Phase 2 편집기는 이 계약만 알고, 그리드 구현체는 교체 가능하다.
- 어댑터를 [01-architecture.md](./01-architecture.md)의 그리드 어댑터(P4) 뒤에 두므로 라이브러리 선택이 이후 전체를 인질로 잡지 않는다.

### 7.2 라이브러리 선정

기준 C1(붙여넣기 ★★★)·C3(대량 컬럼 성능 ★★★)을 1순위, 동률 시 C7(성숙도)로 판정한다(§5).

| 후보 | C1 붙여넣기 | C3 200컬럼 성능 | C7 성숙도 | 판정 |
|------|-------------|-----------------|-----------|------|
| **Glide Data Grid** | 범위 선택 + copy/paste 내장 | Canvas 렌더링으로 대량 셀 최상급 | 커뮤니티/유지보수 활발 | **1순위 채택** |
| RevoGrid | 클립보드 내장 | DOM 기반, 컬럼 그룹 기본 제공 | 상대적으로 작음 | 대안(fallback) |
| AG Grid Community | 범위선택·클립보드 없음(Enterprise 전용) | 최상 | 최상 | 탈락(기존 실패 재현 위험) |

**채택: Glide Data Grid.** 근거 — 200 컬럼 × 다중 조건 행 규모에서 성능(C3)이 핵심이고 Canvas 렌더링이 유리하며, 엑셀 범위 붙여넣기(C1)를 기본 제공한다. MIT·npm 자체 번들이라 폐쇄망(C8)에도 적합하다. 커스텀 에디터/셀 상태 렌더링을 직접 그려야 하는 비용은 위 어댑터 인터페이스가 흡수한다.

**대안 유지: RevoGrid.** 엑셀 유사 UX·컬럼 그룹 기본 기능을 그대로 쓰는 이점이 Phase 2 편집기 구현 중 더 크다고 판단되면 어댑터 구현체만 교체한다.

> 확인 게이트: 시나리오 3(붙여넣기)·2(성능)의 대화형 체감 검증은 Phase 2 편집기 착수 첫 스텝에서 확정 라이브러리로 재확인한다. 판정이 뒤집히면 어댑터 뒤 구현체만 RevoGrid로 교체하며, 어댑터 계약·상위 코드는 불변이다.
