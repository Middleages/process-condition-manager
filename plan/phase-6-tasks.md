# Phase 6 — 전산 출력 (작업 계획)

> 목표: 승인본을 3종 포맷(Type A/B/C)으로 미리보고 Excel로 내려받게 한다. 출력은 **승인본(스냅샷 동결본)만** 대상으로 하며, 출력 전 품질 리포트와 출력 이력(감사)을 남긴다.

관련 문서: [02-data-model.md](./02-data-model.md) · [04-roadmap.md](./04-roadmap.md)

선행 조건: Phase 5 완료 (Approved 프로젝트 + 파라미터 스냅샷 존재). **출력 포맷 요구 재확정 필요** — 기존 시스템의 Type A/B/C 요구는 재검토 후 확정한다(로드맵 명시). 용어 사전에서 전산출력 항목이 의도적으로 제외되어 있으므로, 이 Phase 착수 시 출력 도메인 용어를 용어 사전에 복원한다.

## 완료 기준 (Exit Criteria)

- [ ] EC1. 승인본을 3종 포맷으로 출력·다운로드할 수 있다 (단건 + 벌크 ZIP)
- [ ] EC2. 출력 이력이 조회된다 (누가/언제/어떤 프로젝트를/어떤 포맷으로)
- [ ] EC3. 출력 전 데이터 품질 리포트가 표시된다 (빈 셀/경고 요약)
- [ ] EC4. 출력물의 컬럼 구성이 승인 시점 스냅샷과 일치한다 (live 레지스트리 변경에 영향받지 않음)

## 작업 분해 (Work Breakdown)

의존 관계: T0 → T1 → {T2, T3}.

```mermaid
flowchart LR
    T0[T0 포맷 사양 확정] --> T1[T1 출력 엔진]
    T1 --> T2[T2 미리보기 + 다운로드]
    T1 --> T3[T3 품질 리포트 + 출력 이력]
```

### T0. 출력 포맷 사양 확정

- 기존 Type A/B/C 산출물 샘플 확보 → 실사용자와 유효성 재검토 (P6-D1)
- 포맷별 사양서 작성: 시트 구성, 헤더/컬럼 규칙(스냅샷의 display_name/카테고리 사용), 셀 서식, 파일명 규칙
- 포맷 정의를 코드에 하드코딩할지, 선언적 템플릿(포맷 정의 데이터)으로 둘지 결정 — 3종이 구조적으로 유사하면 선언적 정의 권장 (P1 원칙의 연장)
- 출력 도메인 용어를 [domain-glossary.md](./domain-glossary.md)에 복원

산출물: 포맷 3종 사양서 (plan/ 하위 또는 본 문서 부록).

### T1. 출력 엔진

- `features/export/`: 승인본 조회(스냅샷 컬럼 정의 + cell_value) → 포맷 변환 → xlsx 생성(openpyxl 계열, 폐쇄망 번들 가능 라이브러리)
- 포맷 변환 로직은 입력(컬럼 정의 + 매트릭스)과 출력(시트 구조)만 아는 순수 계층으로 분리 — 단위 테스트 용이
- **스냅샷 기준 렌더링**: 컬럼 구성·표시명·선택지 표시가 전부 `parameter_snapshot`에서 나옴 (EC4의 근거)
- Approved/Archived 외 상태 요청은 거부 (P6-D2)

산출물: 3종 변환 엔진 + 스냅샷 기준 단위 테스트. **EC4 충족.**

### T2. 미리보기 + 다운로드

- `GET /projects/{id}/export/preview?format=` — 화면용 미리보기 (상위 N행 또는 요약 구조)
- `GET /projects/{id}/export?format=` — 단건 xlsx 다운로드 (스트리밍 응답)
- `POST /export/bulk` — 프로젝트 다중 선택 → ZIP (P6-D3, P6-D4 정책)
- UI: 승인본 상세에 출력 탭 — 포맷 선택, 미리보기, 다운로드 버튼; 프로젝트 목록에 벌크 선택 → 일괄 출력

산출물: 미리보기 + 단건/벌크 다운로드. **EC1 충족.**

### T3. 품질 리포트 + 출력 이력

- **품질 리포트**: 출력 전 요약 — 빈 셀 수(layer/카테고리별), 검증 warning 잔존 수(승인 게이트는 error만 차단하므로 warning은 남을 수 있음). 출력 화면에 표시, 출력 차단은 하지 않음
- **출력 이력**: `export_history` 테이블 (project_id, version, format, actor, created_at, 파일명) + 마이그레이션 — 감사 목적, append-only
- 이력 조회 API + UI (프로젝트별 / 전체 관리자 뷰)

산출물: 리포트 + 이력 기록/조회. **EC2·EC3 충족.**

## 실행 순서 요약

1. T0 포맷 사양 확정 ← 외부 입력(샘플) 필요, 최우선 착수
2. T1 출력 엔진
3. T2 미리보기 + 다운로드 / T3 품질 리포트 + 이력 (병행)
4. EC1~EC4 점검 → 재구축 로드맵 완료, 운영 이관 판단
