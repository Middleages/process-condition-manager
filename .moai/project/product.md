# PCM (Process Condition Manager) - 제품 개요

## 프로젝트 정보

**프로젝트명**: Process Condition Manager (PCM)

**목적**: 반도체 Photo 공정의 공정조건표를 웹 기반으로 관리하는 통합 시스템

**버전**: Phase 2 완료 (Phase 3 진행 예정)

---

## 프로젝트 설명

PCM은 반도체 제조 공정 중 Photo 공정의 복잡한 공정조건표를 효율적으로 관리하기 위한 웹 애플리케이션입니다. 제품당 약 300개의 파라미터 컬럼과 30~60개의 레이어로 구성된 대규모 조건 데이터를 편집, 검증, 승인, 출력하는 전체 라이프사이클을 지원합니다.

기존 Excel 기반 관리의 한계를 극복하고, 실시간 협업, 변경 이력 추적, 체계적인 승인 프로세스를 통해 공정 관리의 정확성과 효율성을 획기적으로 개선합니다.

## 핵심 기능

### 1. 프로젝트 관리
**Backbone 기반 프로젝트 생성**: 기존 양산 제품의 조건표를 Backbone으로 활용하여 신규 프로젝트 초안을 자동 생성합니다. 이를 통해 검증된 조건을 기반으로 빠르게 작업을 시작할 수 있습니다.

**상태 워크플로우 관리**: Draft → Review → Approved → Archived의 명확한 상태 흐름을 통해 작업 진행 상황을 추적하고 품질을 보장합니다.

**프로젝트 검색 및 필터링**: 제품명, 상태, 작성자, 작성일 등 다양한 조건으로 프로젝트를 검색하고 관리할 수 있습니다.

### 2. Backbone 관리
**전체 Backbone 복사**: 신규 프로젝트 생성 시 선택한 제품의 전체 조건표를 복사하여 초안을 생성합니다.

**레이어별 Backbone 교체**: 특정 레이어만 다른 제품의 조건으로 교체할 수 있습니다. 예를 들어, 일부 레이어는 A 제품의 조건을, 다른 레이어는 B 제품의 조건을 사용하는 혼합 구성이 가능합니다.

**변경 이력 자동 기록**: Backbone 복사 및 교체 시 모든 셀 변경 사항이 change_logs 테이블에 자동 기록되어 추적 가능합니다.

### 3. 조건표 편집
**AG Grid 기반 고성능 편집기**: 대규모 데이터를 효율적으로 표시하고 편집할 수 있는 AG Grid Community Edition을 활용합니다.

**카테고리별 탭 구성**: SP (Standard Process), SC (Step Combine), OVL (Overlay), DEV (Development) 4개 카테고리로 컬럼을 그룹핑하여 직관적인 편집 환경을 제공합니다.

**실시간 임시저장**: 30초 간격으로 자동 임시저장되어 브라우저 종료 등 예기치 않은 상황에서 데이터 유실을 방지합니다.

**명시적 저장**: 저장 버튼 클릭 시 모든 변경사항이 서버에 반영되고 변경 이력이 기록됩니다.

### 4. 실시간 검증
**셀 단위 실시간 검증**: 각 셀 편집 시 즉시 검증 규칙을 적용하여 오류를 조기에 발견합니다.

**다양한 검증 규칙**:
- Range 검증: 숫자 값의 최소/최대 범위 체크
- Required 검증: 필수 입력 항목 체크
- Conditional Required 검증: 특정 조건 하에서의 필수 입력 체크
- Pattern 검증: 정규식 기반 형식 검증

**시각적 피드백**: 검증 오류가 있는 셀은 빨간색으로 표시되어 즉시 확인 가능합니다.

**검증 오류 목록**: 전체 검증 오류를 목록으로 확인하고 해당 셀로 바로 이동할 수 있습니다.

### 5. Recipe XML 반영
**XML 업로드**: 설비에서 추출한 Recipe XML 파일을 업로드합니다.

**Diff 생성**: 매핑 테이블을 기반으로 XML 데이터와 현재 조건표의 차이를 자동 계산합니다.

**선택적 적용**: Diff 결과를 확인하고 필요한 변경사항만 선택하여 조건표에 반영할 수 있습니다.

**변경 이력 기록**: Recipe XML로부터 반영된 모든 변경사항이 change_source가 'recipe'로 기록됩니다.

### 6. 변경 이력 추적
**셀 단위 추적**: 모든 셀 변경사항을 개별적으로 추적합니다.

**변경 소스 구분**:
- manual: 사용자가 직접 편집한 변경
- backbone: Backbone 복사/교체로 인한 변경
- recipe: Recipe XML 반영으로 인한 변경

**사용자 정보**: 변경한 사용자와 변경 시간을 기록합니다.

**변경 전후 값**: 이전 값과 새로운 값을 모두 저장하여 변경 내역을 완전히 추적합니다.

### 7. Revision 관리
**버전 관리**: 승인된 조건표는 버전 번호가 관리되며, 새로운 Revision 생성 시 자동으로 증가합니다.

**Revision 생성**: Approved 상태의 프로젝트에서 개정이 필요할 경우, 새로운 Draft(버전+1)를 생성하고 기존 프로젝트는 Archived 상태로 전환됩니다.

**버전 히스토리**: 동일 제품의 모든 버전을 추적하고 비교할 수 있습니다.

## 주요 유스케이스

### 신규 제품 조건표 작성
1. 공정 엔지니어가 유사한 양산 제품을 Backbone으로 선택하여 프로젝트 생성
2. 생성된 초안을 기반으로 필요한 레이어 및 파라미터 수정
3. 실시간 검증을 통해 오류 확인 및 수정
4. 검증 통과 후 Review 상태로 전환하여 검토 요청

### Recipe XML 데이터 반영
1. 설비에서 Recipe XML 파일 추출
2. PCM에 XML 업로드 및 Diff 생성
3. Diff 결과 검토 후 필요한 변경사항 선택
4. 선택한 항목을 조건표에 적용하고 저장

### 레이어별 Backbone 교체
1. 특정 레이어의 조건을 다른 제품의 조건으로 교체 필요 시
2. 해당 레이어 선택 후 소스 제품 및 레이어 지정
3. 교체 실행 및 변경 내역 자동 기록
4. 검증 후 저장

### 승인 및 개정 프로세스
1. Draft 작성 완료 후 검증 오류 0건 확인
2. Review 상태로 전환하여 검토자에게 통知
3. 검토자가 내용 확인 후 승인 또는 반려
4. 승인 시 Approved 상태로 전환, 반려 시 Draft로 복귀
5. 추후 개정 필요 시 Revision 생성하여 새로운 버전 작업
